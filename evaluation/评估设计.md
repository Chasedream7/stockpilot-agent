# 评估设计：优化后 StockPilot Agent

## 决策问题，而非泛化打分

这套评估的目标不是证明“Agent 平均分高”，而是回答以下五个可行动的业务问题。每个问题都映射到固定 case、可计算字段和失败后的工程动作。

| 问题 | 要验证的能力 | case | 主指标 | 结果如何使用 |
| --- | --- | --- | --- | --- |
| **Q1：财报、指引或监管问题中，Agent 主动补 SEC 一手来源的成功率是多少？失败后 Critic 能否识别？** | 一手来源检索与失败护栏 | E01–E06、L01–L04、A04、M01、M04 | SEC 发起率、成功获取率、失败识别率 | 失败识别低：修 Critic 的证据护栏；成功获取低：修路由、数据源或重试策略。 |
| **Q2：用户输入模糊或极短时，Agent 是走错路径，还是路径正确但证据不足？** | 不确定性处理 | A01–A04 | 路径正确/错误 × 证据充分/不足二维矩阵 | 前者优先修意图/工具选择；后者优先追问、降级表述或补证据。 |
| **Q3：Critic 对用户下一句话（accept、ask_for_evidence、retry）的预测，与预期反应有多大偏差？** | 自检校准 | 全部 28 条 | 准确率、按类别混淆矩阵、错例数 | 某类召回低：修 Critic prompt/标签定义；不能将 Critic 自己的预测当满意度。 |
| **Q4：首次研究时，Supervisor 能否从完整工具列表中选对第一项证据工具？** | LLM 自主选工具 | R01–R06、E01–E06、L01–L04、C01–C04、A01–A04 | 首动作匹配率 | 只解读 llm_fixture；规则基线仅说明降级路径。 |
| **Q5：用户追问时，Agent 是否复用研究记忆并只补缺失证据？** | session memory、指代解析、最小补检索 | M01–M04 | 首步 self_check 率、无重分析复用率、SEC 补取对齐率 | 出现全流程重跑：修 state 初始化或 Supervisor 的 follow-up 约束。 |

## 标注协议

每条 case 有以下人工标注：

- expected_first_action：不将 PM 的 analyze_goal 计入；衡量 Supervisor 首个工作流动作。
- expects_primary_source：本回合结束时是否必须拥有可用一手来源。
- expected_sec_fetch：本回合是否应新发起 SEC 调用。它允许 M03 这类追问复用上一轮已取得的 SEC 证据。
- expected_user_followup：case 作者在不看 Agent 输出时，为用户可能下一句做的盲标代理。

Q3 的标签不是线上真实用户反馈，因此报告中必须称为“预测对齐/校准代理”，不能称为真实满意度。上线后应把真实继续追问、索要证据、重试/放弃等事件与人工盲审合并分析。

## 判定口径

### Q1：一手来源

- 成功 fixture：要求既出现 fetch_sec_filings，又在结果中存在至少一条 filings；两者不可互相替代。
- 失败 fixture：Critic 只有同时输出 needs_more_evidence 和 ask_for_evidence 才算正确识别。

### Q2：路径和证据要拆开

路径正确表示 route_score 为 100，即所需步骤、首动作、SEC 行为和正常结束均符合 case 标注。证据充分表示 evidence_score 大于等于 50。矩阵的四类结果是：

1. 路径正确且证据充分：可继续评估回答质量。
2. 路径正确但证据不足：不应被流畅 memo 掩盖，应追问或降级。
3. 路径错误但证据充分：工具策略仍有浪费或偏离。
4. 路径错误且证据不足：优先修路由与安全退出。

### Q3：Critic 校准

每个 case 将 predicted_user_followup 与 expected_user_followup 精确匹配。summary 输出预期标签为行、预测标签为列的三分类混淆矩阵，以免总体准确率掩盖少数 retry 或 ask_for_evidence 的漏判。

### Q4：首工具选择

财报/监管/filing 类型的首次请求期望直接先取 SEC；新闻、风险、催化和模糊的一般首次请求期望先取新闻。这个问题要用固定模型、固定 prompt、固定运行日期的 llm_fixture 复测；规则 fallback 的固定新闻优先顺序不应被包装成“LLM 自主选择”。

### Q5：多轮研究记忆

M01–M04 先执行 seed_mission，再把其 memo 和结构化 memory 传给追问回合。合格追问必须先 self_check；不得再次执行 collect_news、analyze_sentiment 或 assess_risk；只在当前问题需要且历史没有一手来源时调用 SEC。M04 特意让 SEC 失败，验证 Agent 会暴露缺口而非重写一份貌似完整的 memo。

## 可复现性与报告方式

离线 fixture 运行用于回归测试和定位逻辑缺陷；LLM 运行用于观察自主决策。两类结果必须分目录保存、分开报告，并在 LLM 报告中记录模型、prompt 版本、运行日期、样本版本和失败 trace。低分、边界和高分 case 都应抽样做人工盲审。
